## Disputes (evidence)

* **LPX-SAST-002 (`'success'` vs `'status'`)** — `src/Support/ResponseHelper.php:25-37`: `generate()` returns
  `['success' => $success, 'message' => $message, 'data' => …]`; there is no `'status'` key (class docblock lines 7-10 say the same).
  `createUbuntuVMWithSSH()` checking `$sshKeyPair['success']` is correct, and the `GenerateSSHKeyTest` stub is shape-accurate.
  The "100% deterministic throw" claim is false; the report's quoted `generate()` snippet (`'status' => $status`) does not match the file.
  The real inversion in LPX-SAST-001 is nonetheless genuine and fixed.
* **LPX-SAST-003 (`http://` accepted)** — `src/ProxmoxAccess.php:126-129`: `baseUrl()` is `return "https://{$this->host}:{$this->port}/api2/json";`
  with no scheme sniffing. `host = 'http://pve'` yields `https://http://pve:8006/…` (invalid URL), never a cleartext request. The quoted `str_starts_with($host,'http://')` branch does not exist at HEAD.
  `CURLOPT_PROTOCOLS` hardening is optional defence-in-depth and was not added (no drive-by).
* **LPX-SAST-004 sub-item** — `src/ProxmoxStorage.php:163` already has `#[\SensitiveParameter] string $password`.

## Behaviour changes worth noting

* `ConnectionException` message is now `Proxmox cURL error (<errno>): <curl_strerror text>`; `ApiException` message carries only the URL path (`/api2/json/…`).
* `createUbuntuVMWithSSH()` result gains a `generated_key` array (only when the key was auto-generated; contains the one-time passphrase — treat as a secret).
* `attachDisk()` returns a failure envelope if `storage`/`format`/`cache`/`iothread` contain anything outside `[A-Za-z0-9._-]`.
